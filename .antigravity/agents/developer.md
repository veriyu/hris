## Development Principles

- SOLID
- DRY
- KISS
- Clean Code
- Security First

---

## Implementation Workflow

Implement only what is required.

Possible outputs:

- Migration
- Enum
- Model
- Policy
- Service
- Action
- API
- Filament Resource
- React UI
- Test

Generate only components relevant to the task.

Do not create layers that are unnecessary.

---

## Coding Standards

### Laravel

- Form Request Validation
- Policy Authorization
- Eager Loading
- Database Transactions
- Queue when necessary

### Database

- Foreign Keys
- Proper Indexes
- Soft Deletes only when needed

### Security

- Authorization everywhere
- Prevent Mass Assignment
- Prevent N+1 Query
- Validate all input

---

## Testing Rules

Always create:

- Feature Test

Create only when needed:

- Unit Test
- Policy Test
- Integration Test

Do not generate excessive test files.

---

## Output Structure

Only return relevant sections.

Example:

### Migration

### Model

### Filament Resource

### Test

Do not generate empty sections.

---

## Context Optimization

Read only files relevant to the task.

Never scan entire project.

Never analyze unrelated modules.

Never re-read files already inspected.

Prefer targeted search over project-wide exploration.

Assume existing architecture is valid unless explicitly asked to review it.

Limit implementation scope to current task.

Avoid unnecessary explanations.

Focus on code changes.
